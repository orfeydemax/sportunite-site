# Анализатор Интеграции Токенов

## Назначение

Систематически анализирует кодовую базу на предмет проблем безопасности, связанных с токенами, используя чеклист интеграции токенов от Trail of Bits:

1. **Реализации Токенов**: Анализ соответствия вашего токена стандартам ERC20/ERC721 или наличие нестандартного поведения.
2. **Интеграции Токенов**: Анализ того, как ваш протокол обрабатывает произвольные токены, включая странные/нестандартные.
3. **On-chain Анализ**: Запрос развернутых контрактов для проверки дефицита, распределения и конфигурации.
4. **Оценка Безопасности**: Выявление рисков из 20+ известных паттернов странных токенов.

**Фреймворк**: Building Secure Contracts - Token Integration Checklist + Weird ERC20 Database

## Как Это Работает

### Фаза 1: Обнаружение Контекста
Определяет контекст анализа:
- **Реализация токена**: Вы создаете контракт токена?
- **Интеграция токена**: Ваш протокол взаимодействует с внешними токенами?
- **Платформа**: Ethereum, другие EVM-цепочки или другая платформа?
- **Типы токенов**: ERC20, ERC721 или оба?

### Фаза 2: Анализ Slither (если Solidity)
Для проектов на Solidity я помогу запустить:
- `slither-check-erc` - проверки соответствия ERC
- `slither --print human-summary` - анализ сложности и обновлений
- `slither --print contract-summary` - анализ функций
- `slither-prop` - генерация свойств для тестирования

### Фаза 3: Анализ Кода
Анализирует:
- Композицию и сложность контракта
- Привилегии владельца и риски централизации
- Соответствие ERC20/ERC721
- Известные паттерны странных токенов
- Паттерны безопасной интеграции

### Фаза 4: On-chain Анализ (если развернут)
Если вы предоставите адрес контракта, я запрошу:
- Дефицит и распределение токенов
- Общее предложение и концентрацию держателей
- Листинги на биржах
- On-chain конфигурацию

### Фаза 5: Оценка Рисков
Предоставляет:
- Выявленные уязвимости
- Нестандартное поведение
- Риски интеграции
- Приоритетные рекомендации

## Категории Оценки

Я проверяю 10 всесторонних категорий, охватывающих все аспекты безопасности токенов. Для подробных критериев, паттернов и чеклистов см. [ASSESSMENT_CATEGORIES.md](resources/ASSESSMENT_CATEGORIES.md).

### Краткий Справочник:

1. **Общие Соображения** - Аудиты безопасности, прозрачность команды, контакты по безопасности
2. **Композиция Контракта** - Анализ сложности, использование SafeMath, количество функций, точки входа
3. **Привилегии Владельца** - Возможность обновления, минтинг, возможность паузы, черные списки, подотчетность команды
4. **Соответствие ERC20** - Возвращаемые значения, метаданные, decimals, гонки условий, проверки Slither
5. **Риски Расширений ERC20** - Внешние вызовы/хуки, комиссии за перевод, токены с ребейзом/доходом
6. **Анализ Дефицита Токенов** - Распределение предложения, концентрация держателей, распределение по биржам, риски флеш-лоунов/минтинга
7. **Паттерны Странных ERC20** (24 паттерна, включая):
   - Реентерабельные вызовы (хуки ERC777)
   - Отсутствующие возвращаемые значения (USDT, BNB, OMG)
   - Комиссия при переводе (STA, PAXG)
   - Изменение баланса вне переводов (Ampleforth, Compound)
   - Обновляемые токены (USDC, USDT)
   - Флеш-минтинг (DAI)
   - Блок-листы (USDC, USDT)
   - Токены с паузой (BNB, ZIL)
   - Защита от гонки утверждений (USDT, KNC)
   - Откат при утверждении/переводе на нулевой адрес
   - Откат при утверждении/переводе нулевого значения
   - Несколько адресов токена
   - Малое количество decimals (USDC: 6, Gemini: 2)
   - Большое количество decimals (YAM-V2: 24)
   - transferFrom с src == msg.sender
   - Нестроковые метаданные (MKR)
   - Нет отката при сбое (ZRX, EURS)
   - Откат при больших утверждениях (UNI, COMP)
   - Инъекция кода через имя токена
   - Необычная функция permit (DAI, RAI, GLM)
   - Перевод меньше суммы (cUSDCv3)
   - Представление нативной валюты как ERC-20 (Celo, Polygon, zkSync)
   - [И многое другое...](resources/ASSESSMENT_CATEGORIES.md#7-weird-erc20-patterns)
8. **Безопасность Интеграции Токенов** - Паттерны безопасного перевода, проверка баланса, белые списки, обертки, защитные паттерны
9. **Соответствие ERC721** - Перевод на 0x0, safeTransferFrom, метаданные, ownerOf, очистка утверждений, неизменяемость ID токена
10. **Общие Риски ERC721** - Реентерабельность onERC721Received, безопасный минтинг, очистка утверждений при сжигании

### Найдены Критические Проблемы

❌ **Паттерн 7.2: Отсутствующие Возвращаемые Значения**
**Найдено в:** Интеграция USDT
Файл: contracts/Vault.sol:156
```solidity
IERC20(usdt).transferFrom(msg.sender, address(this), amount);
// Нет проверки возвращаемого значения! USDT не возвращает bool
```

**Риск:** Тихие сбои при переводах USDT
**Эксплойт:** Пользователь кажется внес депозит, но токены не переместились
**Исправление:** Использовать обертку OpenZeppelin SafeERC20

---

❌ **Паттерн 7.3: Комиссия при Переводе**
**Риск для:** Любого токена с комиссиями за перевод
Файл: contracts/Vault.sol:170
```solidity
uint256 balanceBefore = IERC20(token).balanceOf(address(this));
token.transferFrom(msg.sender, address(this), amount);
shares = amount * exchangeRate;  // НЕПРАВИЛЬНО! Нужно использовать фактически полученную сумму
```

**Риск:** Несоответствие учета, если токен берет комиссию
**Эксплойт:** Пользователю начислено больше долей, чем внесено токенов
**Исправление:** Рассчитывать доли из `balanceAfter - balanceBefore`

## Обоснования (Не Пропускать)

| Обоснование | Почему Это Неверно | Требуемое Действие |
|-------------|--------------------|--------------------|
| "Токен выглядит стандартным, тесты ERC20 проходят" | 20+ паттернов странных токенов существуют за пределами соответствия ERC20 | Проверить ВСЕ паттерны странных токенов из базы данных (отсутствие возврата, откат при нуле, хуки и т.д.) |
| "Slither не показывает проблем, интеграция безопасна" | Slither обнаруживает некоторые паттерны, упускает логику интеграции | Выполнить полный ручной анализ всех 5 критериев интеграции токенов |
| "Комиссия при переводе не обнаружена, пропускаем эту проверку" | Комиссия при переводе может контролироваться владельцем или быть условной | Протестировать все сценарии перевода, проверить логику условных комиссий |
| "Проверки баланса существуют, обработка безопасна" | Проверки баланса сами по себе не защищают от всех странных токенов | Проверить обертки безопасного перевода, обработку откатов, паттерны утверждения |
| "Токен развернут авторитетной командой, считаем стандартным" | Репутация не гарантирует стандартного поведения | Анализировать реальный код и поведение on-chain, не доверять предположениям |
| "Интеграция использует OpenZeppelin, должно быть безопасно" | Библиотеки OpenZeppelin не защищают от странных внешних токенов | Проверить защитные паттерны вокруг всех вызовов внешних токенов |
| "Не могу запустить Slither, пропускаю автоматический анализ" | Slither предоставляет критические проверки соответствия ERC | Вручную проверить все критерии slither-check-erc или задокументировать, почему заблокировано |
| "Этот паттерн кажется нормальным" | Интуиция упускает тонкие баги интеграции токенов | Систематически проверить все 20+ паттернов странных токенов с доказательствами в коде |
