# Выполнение Планов (Executing Plans)

## Обзор

Загрузите план, критически просмотрите, выполняйте задачи пакетами, отчитывайтесь для проверки между пакетами.

**Основной принцип:** Пакетное выполнение с контрольными точками для проверки архитектором.

**Объявите в начале:** "Я использую навык executing-plans для реализации этого плана."

## Процесс

### Шаг 1: Загрузка и Просмотр Плана
1. Прочитайте файл плана
2. Критически просмотрите - определите любые вопросы или опасения по поводу плана
3. Если есть опасения: Поднимите их с вашим партнером-человеком перед началом
4. Если опасений нет: Создайте список задач и приступайте

### Шаг 2: Выполнение Пакета
**По умолчанию: Первые 3 задачи**

Для каждой задачи:
1. Отметьте как in_progress (в процессе)
2. Следуйте каждому шагу в точности (план имеет небольшие шаги)
3. Запускайте проверки, как указано
4. Отметьте как completed (выполнено)

### Шаг 3: Отчет
Когда пакет завершен:
- Покажите, что было реализовано
- Покажите вывод проверки
- Скажите: "Готов к обратной связи."

### Шаг 4: Продолжение
На основе обратной связи:
- Примените изменения, если необходимо
- Выполняйте следующий пакет
- Повторяйте до завершения

### Шаг 5: Завершение Разработки

После того как все задачи выполнены и проверены:
- Объявите: "Я использую навык finishing-a-development-branch для завершения этой работы."
- **ТРЕБУЕМЫЙ ПОДНАВЫК:** Используйте superpowers:finishing-a-development-branch
- Следуйте этому навыку, чтобы проверить тесты, представить варианты, выполнить выбор

## Когда Остановиться и Попросить Помощи

**ОСТАНАВЛИВАЙТЕ выполнение немедленно, когда:**
- Столкнулись с блокером в середине пакета (отсутствует зависимость, тест не проходит, инструкция неясна)
- В плане есть критические пробелы, мешающие началу
- Вы не понимаете инструкцию
- Проверка не проходит неоднократно

**Просите разъяснений, а не угадывайте.**

## Когда Возвращаться к Ранее Пройденным Шагам

**Вернитесь к Просмотру (Шаг 1), когда:**
- Партнер обновляет план на основе вашей обратной связи
- Фундаментальный подход требует переосмысления

**Не пробивайтесь через блокеры силой** - остановитесь и спросите.

## Помните
- Сначала критически просмотрите план
- Следуйте шагам плана в точности
- Не пропускайте проверки
- Ссылайтесь на навыки, когда план говорит об этом
- Между пакетами: просто отчитайтесь и ждите
- Останавливайтесь, когда заблокированы, не угадывайте
- Никогда не начинайте реализацию в ветке main/master без явного согласия пользователя
