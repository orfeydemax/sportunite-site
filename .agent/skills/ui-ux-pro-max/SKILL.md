# UI/UX Pro Max - Интеллект Дизайна

Комплексное руководство по дизайну для веб- и мобильных приложений. Содержит 50+ стилей, 97 цветовых палитр, 57 шрифтовых пар, 99 руководств по UX и 25 типов диаграмм для 9 технологических стеков. База данных с возможностью поиска и рекомендациями на основе приоритетов.

## Когда Применять

Используйте эти рекомендации, когда:
- Проектируете новые UI компоненты или страницы
- Выбираете цветовые палитры и типографику
- Проверяете код на наличие UX проблем
- Создаете целевые страницы или дашборды
- Реализуете требования доступности

## Быстрый Справочник

### 1. Доступность (КРИТИЧЕСКОЕ)

- `color-contrast` - Минимальное соотношение 4.5:1 для обычного текста
- `focus-states` - Видимые кольца фокуса на интерактивных элементах
- `alt-text` - Описательный alt текст для значимых изображений
- `aria-labels` - aria-label для кнопок, состоящих только из иконок
- `keyboard-nav` - Порядок табуляции соответствует визуальному порядку
- `form-labels` - Используйте label с атрибутом for

### 2. Касание и Взаимодействие (КРИТИЧЕСКОЕ)

- `touch-target-size` - Минимальный размер цели касания 44x44px
- `hover-vs-tap` - Используйте click/tap для основных взаимодействий
- `loading-buttons` - Отключайте кнопку во время асинхронных операций
- `error-feedback` - Четкие сообщения об ошибках рядом с проблемой
- `cursor-pointer` - Добавьте cursor-pointer к кликабельным элементам

### 3. Производительность (ВЫСОКОЕ)

- `image-optimization` - Используйте WebP, srcset, ленивую загрузку
- `reduced-motion` - Проверяйте prefers-reduced-motion
- `content-jumping` - Резервируйте место для асинхронного контента

### 4. Макет и Адаптивность (ВЫСОКОЕ)

- `viewport-meta` - width=device-width initial-scale=1
- `readable-font-size` - Минимальный размер основного текста 16px на мобильных
- `horizontal-scroll` - Убедитесь, что контент помещается в ширину вьюпорта
- `z-index-management` - Определите шкалу z-index (10, 20, 30, 50)

### 5. Типографика и Цвет (СРЕДНЕЕ)

- `line-height` - Используйте 1.5-1.75 для основного текста
- `line-length` - Ограничьте длину строки 65-75 символами
- `font-pairing` - Сочетайте индивидуальность заголовка и основного шрифта

### 6. Анимация (СРЕДНЕЕ)

- `duration-timing` - Используйте 150-300ms для микровзаимодействий
- `transform-performance` - Используйте transform/opacity, а не width/height
- `loading-states` - Скелетные экраны или спиннеры

### 7. Выбор Стиля (СРЕДНЕЕ)

- `style-match` - Сопоставляйте стиль с типом продукта
- `consistency` - Используйте один и тот же стиль на всех страницах
- `no-emoji-icons` - Используйте SVG иконки, а не эмодзи

### 8. Диаграммы и Данные (НИЗКОЕ)

- `chart-type` - Сопоставляйте тип диаграммы с типом данных
- `color-guidance` - Используйте доступные цветовые палитры
- `data-table` - Предоставьте табличную альтернативу для доступности

## Как Использовать Этот Навык

Когда пользователь запрашивает работу с UI/UX (дизайн, сборка, создание, реализация, обзор, исправление, улучшение), следуйте этому рабочему процессу:

### Шаг 1: Анализ Требований Пользователя

Извлеките ключевую информацию из запроса пользователя:
- **Тип продукта**: SaaS, e-commerce, портфолио, дашборд, лендинг и т.д.
- **Ключевые слова стиля**: минималистичный, игривый, профессиональный, элегантный, темный режим и т.д.
- **Отрасль**: здравоохранение, финтех, игры, образование и т.д.
- **Стек**: React, Vue, Next.js, или по умолчанию `html-tailwind`

### Шаг 2: Генерация Дизайн-Системы (ОБЯЗАТЕЛЬНО)

**Всегда начинайте с `--design-system`**, чтобы получить полные рекомендации с обоснованием:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<тип_продукта> <отрасль> <ключевые слова>" --design-system [-p "Название Проекта"]
```

Эта команда:
1. Ищет в 5 доменах параллельно (продукт, стиль, цвет, лендинг, типографика)
2. Применяет правила рассуждения из `ui-reasoning.csv` для выбора лучших совпадений
3. Возвращает полную дизайн-систему: паттерн, стиль, цвета, типографика, эффекты
4. Включает анти-паттерны, которых следует избегать

**Пример:**
```bash
python3 skills/ui-ux-pro-max/scripts/search.py "beauty spa wellness service" --design-system -p "Serenity Spa"
```

### Шаг 2b: Сохранение Дизайн-Системы (Паттерн Master + Overrides)

Чтобы сохранить дизайн-систему для **иерархического извлечения между сессиями**, добавьте `--persist`:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<query>" --design-system --persist -p "Project Name"
```

Это создает:
- `design-system/MASTER.md` — Глобальный Источник Истины со всеми правилами дизайна
- `design-system/pages/` — Папка для переопределений, специфичных для страниц

**С переопределением для конкретной страницы:**
```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<query>" --design-system --persist -p "Project Name" --page "dashboard"
```

Это также создает:
- `design-system/pages/dashboard.md` — Отклонения от Master, специфичные для страницы

**Как работает иерархическое извлечение:**
1. При создании конкретной страницы (например, "Checkout"), сначала проверьте `design-system/pages/checkout.md`
2. Если файл страницы существует, его правила **переопределяют** файл Master
3. Если нет, используйте исключительно `design-system/MASTER.md`

**Промпт для контекстно-зависимого извлечения:**
```
I am building the [Page Name] page. Please read design-system/MASTER.md.
Also check if design-system/pages/[page-name].md exists.
If the page file exists, prioritize its rules.
If not, use the Master rules exclusively.
Now, generate the code...
```

### Шаг 3: Дополните Детальным Поиском (по необходимости)

После получения дизайн-системы, используйте поиск по доменам для получения дополнительных деталей:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<keyword>" --domain <domain> [-n <max_results>]
```

**Когда использовать детальный поиск:**

| Потребность | Домен | Пример |
|-------------|-------|--------|
| Больше вариантов стиля | `style` | `--domain style "glassmorphism dark"` |
| Рекомендации по диаграммам | `chart` | `--domain chart "real-time dashboard"` |
| Лучшие практики UX | `ux` | `--domain ux "animation accessibility"` |
| Альтернативные шрифты | `typography` | `--domain typography "elegant luxury"` |
| Структура лендинга | `landing` | `--domain landing "hero social-proof"` |

### Шаг 4: Руководства по Стеку (По умолчанию: html-tailwind)

Получите лучшие практики, специфичные для реализации. Если пользователь не указывает стек, **по умолчанию `html-tailwind`**.

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<keyword>" --stack html-tailwind
```

Доступные стеки: `html-tailwind`, `react`, `nextjs`, `vue`, `svelte`, `swiftui`, `react-native`, `flutter`, `shadcn`, `jetpack-compose`

## Общие Правила для Профессионального UI

Это часто упускаемые проблемы, из-за которых UI выглядит непрофессионально:

### Иконки и Визуальные Элементы

| Правило | Делать | Не делать |
|---------|--------|-----------|
| **Никаких иконок-эмодзи** | Используйте SVG иконки (Heroicons, Lucide, Simple Icons) | Использовать эмодзи вроде 🎨 🚀 ⚙️ как UI иконки |
| **Стабильные состояния наведения** | Используйте переходы цвета/прозрачности при наведении | Использовать трансформации масштаба, которые сдвигают макет |
| **Правильные логотипы брендов** | Ищите официальные SVG на Simple Icons | Угадывать или использовать неправильные пути логотипов |
| **Постоянный размер иконок** | Используйте фиксированный viewBox (24x24) с w-6 h-6 | Смешивать разные размеры иконок случайным образом |

### Взаимодействие и Курсор

| Правило | Делать | Не делать |
|---------|--------|-----------|
| **Курсор-указатель** | Добавьте `cursor-pointer` ко всем кликабельным/наводимым карточкам | Оставлять курсор по умолчанию на интерактивных элементах |
| **Обратная связь при наведении** | Обеспечьте визуальную обратную связь (цвет, тень, граница) | Никаких указаний, что элемент интерактивен |
| **Плавные переходы** | Используйте `transition-colors duration-200` | Мгновенные изменения состояния или слишком медленные (>500ms) |

### Контраст Светлого/Темного Режима

| Правило | Делать | Не делать |
|---------|--------|-----------|
| **Стеклянная карточка (светлый)** | Используйте `bg-white/80` или выше прозрачность | Использовать `bg-white/10` (слишком прозрачно) |
| **Контраст текста (светлый)** | Используйте `#0F172A` (slate-900) для текста | Использовать `#94A3B8` (slate-400) для основного текста |
| **Приглушенный текст (светлый)** | Используйте `#475569` (slate-600) минимум | Использовать gray-400 или светлее |
| **Видимость границ** | Используйте `border-gray-200` в светлом режиме | Использовать `border-white/10` (невидимо) |

### Макет и Интервалы

| Правило | Делать | Не делать |
|---------|--------|-----------|
| **Плавающая навигация** | Добавьте `top-4 left-4 right-4` отступы | Приклеивать навигацию к `top-0 left-0 right-0` |
| **Внутренний отступ контента** | Учитывайте фиксированную высоту навигации | Позволять контенту скрываться за фиксированными элементами |
| **Постоянная макс. ширина** | Используйте ту же `max-w-6xl` или `max-w-7xl` | Смешивать разные ширины контейнеров |

## Чек-лист Перед Сдачей

Перед сдачей кода UI, проверьте эти пункты:

### Визуальное Качество
- [ ] Не используются эмодзи в качестве иконок (используйте SVG вместо них)
- [ ] Все иконки из согласованного набора иконок (Heroicons/Lucide)
- [ ] Логотипы брендов правильные (проверено на Simple Icons)
- [ ] Состояния наведения не вызывают сдвига макета
- [ ] Используйте цвета темы напрямую (bg-primary), а не обертку var()

### Взаимодействие
- [ ] Все кликабельные элементы имеют `cursor-pointer`
- [ ] Состояния наведения обеспечивают четкую визуальную обратную связь
- [ ] Переходы плавные (150-300ms)
- [ ] Состояния фокуса видимы для навигации с клавиатуры

### Светлый/Темный Режим
- [ ] Текст в светлом режиме имеет достаточный контраст (минимум 4.5:1)
- [ ] Стеклянные/прозрачные элементы видимы в светлом режиме
- [ ] Границы видимы в обоих режимах
- [ ] Протестируйте оба режима перед сдачей

### Макет
- [ ] Плавающие элементы имеют правильные отступы от краев
- [ ] Контент не скрыт за фиксированными навигационными панелями
- [ ] Адаптивность на 375px, 768px, 1024px, 1440px
- [ ] Нет горизонтальной прокрутки на мобильных

### Доступность
- [ ] Все изображения имеют alt текст
- [ ] Поля форм имеют метки
- [ ] Цвет не является единственным индикатором
- [ ] `prefers-reduced-motion` соблюдается
