# UI/UX Pro Max - Дизайн-интеллект

Комплексное руководство по дизайну для веб- и мобильных приложений. Содержит более 50 стилей, 97 цветовых палитр, 57 комбинаций шрифтов, 99 рекомендаций по UX и 25 типов диаграмм для 9 технологических стеков. База данных с поиском и приоритетными рекомендациями.

## Когда применять

Используйте эти рекомендации при:
- Проектировании новых UI-компонентов или страниц
- Выборе цветовых палитр и типографики
- Проверке кода на наличие проблем с UX
- Создании лендингов или дашбордов
- Внедрении требований доступности (accessibility)

## Быстрая справка

### 1. Доступность (Accessibility) (КРИТИЧЕСКОЕ)

- `color-contrast` — Минимальный коэффициент контрастности 4.5:1 для обычного текста
- `focus-states` — Видимые кольца фокуса на интерактивных элементах
- `alt-text` — Описательный альтернативный текст для значимых изображений
- `aria-labels` — Атрибут aria-label для кнопок, содержащих только иконки
- `keyboard-nav` — Порядок табуляции соответствует визуальному порядку
- `form-labels` — Использование label с атрибутом for

### 2. Касания и взаимодействие (КРИТИЧЕСКОЕ)

- `touch-target-size` — Минимальный размер области касания 44x44px
- `hover-vs-tap` — Использование клика/тапа для основных взаимодействий
- `loading-buttons` — Отключение кнопки во время асинхронных операций
- `error-feedback` — Понятные сообщения об ошибках рядом с проблемой
- `cursor-pointer` — Добавление cursor-pointer к кликабельным элементам

### 3. Производительность (ВЫСОКОЕ)

- `image-optimization` — Использование WebP, srcset, ленивая загрузка
- `reduced-motion` — Проверка правила prefers-reduced-motion
- `content-jumping` — Резервирование места для асинхронного контента

### 4. Макет и адаптивность (ВЫСОКОЕ)

- `viewport-meta` — width=device-width initial-scale=1
- `readable-font-size` — Минимум 16px для основного текста на мобильных устройствах
- `horizontal-scroll` — Контент должен помещаться по ширине экрана
- `z-index-management` — Определение шкалы z-index (10, 20, 30, 50)

### 5. Типографика и цвет (СРЕДНЕЕ)

- `line-height` — 1.5-1.75 для основного текста
- `line-length` — Ограничение до 65-75 символов на строку
- `font-pairing` — Соответствие характеров шрифтов заголовка и основного текста

### 6. Анимация (СРЕДНЕЕ)

- `duration-timing` — 150-300мс для микро-взаимодействий
- `transform-performance` — Использование transform/opacity вместо width/height
- `loading-states` — Скелетон-экраны или спиннеры

### 7. Выбор стиля (СРЕДНЕЕ)

- `style-match` — Соответствие стиля типу продукта
- `consistency` — Использование одного стиля на всех страницах
- `no-emoji-icons` — Использование SVG-иконок вместо эмодзи

### 8. Графики и данные (НИЗКОЕ)

- `chart-type` — Соответствие типа диаграммы типу данных
- `color-guidance` — Использование доступных цветовых палитр
- `data-table` — Наличие альтернативной таблицы для доступности

## Как использовать этот навык

Когда пользователь запрашивает работу над UI/UX (дизайн, сборка, создание, внедрение, обзор, исправление, улучшение), следуйте этому рабочему процессу:

### Шаг 1: Анализ требований пользователя

Извлеките ключевую информацию из запроса:
- **Тип продукта**: SaaS, e-commerce, портфолио, дашборд, лендинг и т. д.
- **Ключевые слова стиля**: минималистичный, игровой, профессиональный, элегантный, темная тема и т. д.
- **Отрасль**: медицина, финтех, гейминг, образование и т. д.
- **Стек**: React, Vue, Next.js или по умолчанию `html-tailwind`

### Шаг 2: Генерация дизайн-системы (ОБЯЗАТЕЛЬНО)

**Всегда начинайте с `--design-system`**, чтобы получить полные рекомендации с обоснованием:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<тип_продукта> <отрасль> <ключевые_слова>" --design-system [-p "Название проекта"]
```

Эта команда:
1. Выполняет параллельный поиск в 5 областях (продукт, стиль, цвет, лендинг, типографика)
2. Применяет правила из `ui-reasoning.csv` для выбора лучших совпадений
3. Возвращает полную дизайн-систему: паттерн, стиль, цвета, типографику, эффекты
4. Включает антипаттерны, которых следует избегать

**Пример:**
```bash
python3 skills/ui-ux-pro-max/scripts/search.py "beauty spa wellness service" --design-system -p "Serenity Spa"
```

### Шаг 2b: Сохранение дизайн-системы (паттерн Master + Overrides)

Чтобы сохранить дизайн-систему для **иерархического извлечения в разных сессиях**, добавьте `--persist`:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<запрос>" --design-system --persist -p "Название проекта"
```

Это создаст:
- `design-system/MASTER.md` — глобальный источник истины со всеми правилами дизайна
- `design-system/pages/` — папка для переопределений (overrides) конкретных страниц

**Пример с переопределением страницы:**
```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<запрос>" --design-system --persist -p "Название проекта" --page "dashboard"
```

Это также создаст:
- `design-system/pages/dashboard.md` — специфичные отклонения от Master для этой страницы

**Как работает иерархическое извлечение:**
1. При создании конкретной страницы (например, "Checkout"), сначала проверьте `design-system/pages/checkout.md`
2. Если файл страницы существует, его правила **перекрывают** файл Master
3. Если нет, используйте исключительно `design-system/MASTER.md`

**Промпт для извлечения с учетом контекста:**
```
Я создаю страницу [Название страницы]. Пожалуйста, прочитай design-system/MASTER.md.
Также проверь, существует ли design-system/pages/[название-страницы].md.
Если файл страницы существует, приоритезируй его правила.
Если нет, используй только правила Master.
Теперь сгенерируй код...
```

### Шаг 3: Дополнение детальным поиском (при необходимости)

После получения дизайн-системы используйте поиск по доменам (областям) для получения дополнительных деталей:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<ключевое_слово>" --domain <domain> [-n <макс_результатов>]
```

**Когда использовать детальный поиск:**

| Потребность | Область (Domain) | Пример |
|-------------|------------------|--------|
| Больше вариантов дизайна | `style` | `--domain style "glassmorphism dark"` |
| Рекомендации по графикам | `chart` | `--domain chart "real-time dashboard"` |
| Рекомендации по UX | `ux` | `--domain ux "animation accessibility"` |
| Альтернативные шрифты | `typography` | `--domain typography "elegant luxury"` |
| Структура лендинга | `landing` | `--domain landing "hero social-proof"` |

### Шаг 4: Рекомендации по стеку (По умолчанию: html-tailwind)

Получите специфические рекомендации по внедрению. Если пользователь не указал стек, **используйте `html-tailwind`**.

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<ключевое_слово>" --stack html-tailwind
```

Доступные стеки: `html-tailwind`, `react`, `nextjs`, `vue`, `svelte`, `swiftui`, `react-native`, `flutter`, `shadcn`, `jetpack-compose`

## Общие правила для профессионального интерфейса

Эти проблемы часто упускаются из виду, что делает интерфейс непрофессиональным:

### Иконки и визуальные элементы

| Правило | Как надо | Как не надо |
|---------|----------|-------------|
| **Без эмодзи в роли иконок** | SVG-иконки (Heroicons, Lucide, Simple Icons) | Использование 🎨 🚀 ⚙️ в интерфейсе |
| **Стабильный ховер** | Плавный переход цвета/прозрачности | Трансформации scale, которые сдвигают макет |
| **Корректные логотипы** | Поиск официальных SVG в Simple Icons | Угадывание или использование неверных путей |
| **Размер иконок** | Фиксированный viewBox (24x24) с w-6 h-6 | Смешивание иконок разного размера |

### Взаимодействие и курсор

| Правило | Как надо | Как не надо |
|---------|----------|-------------|
| **Курсор-указатель** | `cursor-pointer` на всех кликабельных карточках | Стандартный курсор на активных элементах |
| **Обратная связь** | Визуальный отклик (цвет, тень, рамка) | Отсутствие реакции на наведение |
| **Плавность** | `transition-colors duration-200` | Мгновенная смена состояний или слишком медленная |

### Контраст светлой и темной темы

| Правило | Как надо | Как не надо |
|---------|----------|-------------|
| **Стеклянные карты** | `bg-white/80` или выше в светлой теме | `bg-white/10` (слишком прозрачно) |
| **Контраст текста** | `#0F172A` (slate-900) для основного текста | `#94A3B8` (slate-400) для чтения |
| **Приглушенный текст** | Мимум `#475569` (slate-600) | Слишком бледные оттенки серого |
| **Видимость границ** | `border-gray-200` в светлой теме | `border-white/10` (невидимо) |

### Макет и отступы

| Правило | Как надо | Как не надо |
|---------|----------|-------------|
| **Плавающая навигация** | Отступы `top-4 left-4 right-4` | Прилипание вплотную `top-0 left-0 right-0` |
| **Внутренние отступы** | Учет высоты фиксированной навигации | Контент прячется за навигацией |
| **Единая ширина** | Одинаковые `max-w-6xl` или `max-w-7xl` | Разные контейнеры на одной странице |

## Чек-лист перед сдачей

Перед передачей кода, проверьте эти пункты:

### Визуальное качество
- [ ] Не используются эмодзи в качестве иконок (только SVG)
- [ ] Все иконки из одного набора (Heroicons/Lucide)
- [ ] Логотипы брендов верные (проверено в Simple Icons)
- [ ] Ховеры не вызывают сдвиг макета
- [ ] Цвета используются напрямую (bg-primary), а не через var()

### Взаимодействие
- [ ] Все кликабельные элементы имеют `cursor-pointer`
- [ ] Ховеры дают четкую визуальную связь
- [ ] Переходы плавные (150-300мс)
- [ ] Состояния фокуса видимы для навигации с клавиатуры

### Светлая/Темная темы
- [ ] Текст в светлой теме имеет достаточный контраст (минимум 4.5:1)
- [ ] "Стеклянные" элементы видны в светлой теме
- [ ] Рамки видны в обеих темах
- [ ] Обе темы протестированы

### Макет
- [ ] Плавающие элементы имеют отступы от краев
- [ ] Контент не прячется за фиксированными панелями
- [ ] Адаптивность проверена на 375px, 768px, 1024px, 1440px
- [ ] Нет горизонтальной прокрутки на мобильных устройствах

### Доступность
- [ ] У всех изображений есть alt-текст
- [ ] У полей ввода есть лейблы
- [ ] Цвет — не единственный индикатор смысла
- [ ] Настройка `prefers-reduced-motion` соблюдается
