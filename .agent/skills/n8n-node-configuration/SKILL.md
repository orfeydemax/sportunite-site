# Конфигурация Узлов n8n

Экспертное руководство по настройке узлов с учетом операций и зависимостей свойств.

---

## Философия Конфигурации

**Прогрессивное раскрытие**: Начинайте с малого, добавляйте сложность по мере необходимости

Лучшие практики конфигурации:
- `get_node` с `detail: "standard"` — наиболее используемый паттерн обнаружения
- 56 секунд в среднем между правками конфигурации
- Покрывает 95% вариантов использования с ответом в 1-2K токенов

**Ключевая идея**: Большинству конфигураций нужна только стандартная детализация, а не полная схема!

---

## Основные Концепции

### 1. Конфигурация с Учетом Операций

**Не все поля всегда обязательны** — это зависит от операции!

**Пример**: Узел Slack
```javascript
// Для operation='post'
{
  "resource": "message",
  "operation": "post",
  "channel": "#general",  // Обязательно для post
  "text": "Hello!"        // Обязательно для post
}

// Для operation='update'
{
  "resource": "message",
  "operation": "update",
  "messageId": "123",     // Обязательно для update (другое поле!)
  "text": "Updated!"      // Обязательно для update
  // channel НЕ обязательно для update
}
```

**Ключ**: Ресурс + операция определяют, какие поля обязательны!

### 2. Зависимости Свойств

**Поля появляются/исчезают в зависимости от значений других полей**

**Пример**: Узел HTTP Request
```javascript
// Когда method='GET'
{
  "method": "GET",
  "url": "https://api.example.com"
  // sendBody не показан (у GET нет тела)
}

// Когда method='POST'
{
  "method": "POST",
  "url": "https://api.example.com",
  "sendBody": true,       // Теперь видимое!
  "body": {               // Обязательно, когда sendBody=true
    "contentType": "json",
    "content": {...}
  }
}
```

**Механизм**: displayOptions управляют видимостью полей

### 3. Прогрессивное Обнаружение

**Используйте правильный уровень детализации**:

1. **get_node({detail: "standard"})** - ПО УМОЛЧАНИЮ
   - Быстрый обзор (~1-2K токенов)
   - Обязательные поля + общие опции
   - **Используйте первым** - покрывает 95% потребностей

2. **get_node({mode: "search_properties", propertyQuery: "..."})** (для поиска конкретных полей)
   - Поиск свойств по имени
   - Используйте при поиске auth, body, headers и т.д.

3. **get_node({detail: "full"})** (полная схема)
   - Все свойства (~3-8K токенов)
   - Используйте только когда стандартной детализации недостаточно

## Рабочий Процесс Конфигурации

### Стандартный Процесс

```
1. Определите тип узла и операцию
   ↓
2. Используйте get_node (стандартная детализация по умолчанию)
   ↓
3. Настройте обязательные поля
   ↓
4. Проверьте конфигурацию (Validate)
   ↓
5. Если поле неясно → get_node({mode: "search_properties"})
   ↓
6. Добавьте опциональные поля по необходимости
   ↓
7. Проверьте снова
   ↓
8. Разверните (Deploy)
```

### Пример: Настройка HTTP Request

**Шаг 1**: Определите, что вам нужно
```javascript
// Цель: POST JSON к API
```

**Шаг 2**: Получите информацию об узле
```javascript
const info = get_node({
  nodeType: "nodes-base.httpRequest"
});

// Возвращает: method, url, sendBody, body, authentication required/optional
```

**Шаг 3**: Минимальная конфигурация
```javascript
{
  "method": "POST",
  "url": "https://api.example.com/create",
  "authentication": "none"
}
```

**Шаг 4**: Проверка
```javascript
validate_node({
  nodeType: "nodes-base.httpRequest",
  config,
  profile: "runtime"
});
// → Ошибка: "sendBody required for POST"
```

**Шаг 5**: Добавьте обязательное поле
```javascript
{
  "method": "POST",
  "url": "https://api.example.com/create",
  "authentication": "none",
  "sendBody": true
}
```

**Шаг 6**: Проверьте снова
```javascript
validate_node({...});
// → Ошибка: "body required when sendBody=true"
```

**Шаг 7**: Завершите конфигурацию
```javascript
{
  "method": "POST",
  "url": "https://api.example.com/create",
  "authentication": "none",
  "sendBody": true,
  "body": {
    "contentType": "json",
    "content": {
      "name": "={{$json.name}}",
      "email": "={{$json.email}}"
    }
  }
}
```

**Шаг 8**: Финальная проверка
```javascript
validate_node({...});
// → Valid! ✅
```

## Уровни Детализации get_node

### Стандартная Детализация (ПО УМОЛЧАНИЮ - Используйте Это!)

**✅ Начало конфигурации**
```javascript
get_node({
  nodeType: "nodes-base.slack"
});
// detail="standard" по умолчанию
```

**Возвращает** (~1-2K токенов):
- Обязательные поля
- Общие опции
- Список операций
- Метаданные

**Использование**: 95% потребностей конфигурации

### Полная Детализация (Используйте Осторожно)

**✅ Когда стандарта недостаточно**
```javascript
get_node({
  nodeType: "nodes-base.slack",
  detail: "full"
});
```

**Возвращает** (~3-8K токенов):
- Полная схема
- Все свойства
- Все вложенные опции

**Предупреждение**: Большой ответ, используйте только если стандартного недостаточно

### Режим Поиска Свойств

**✅ Поиск конкретного поля**
```javascript
get_node({
  nodeType: "nodes-base.httpRequest",
  mode: "search_properties",
  propertyQuery: "auth"
});
```

**Использование**: Поиск аутентификации, заголовков, полей тела и т.д.

### Дерево Решений

```
┌─────────────────────────────────┐
│ Начинаете новую настройку узла? │
├─────────────────────────────────┤
│ ДА → get_node (standard)        │
└─────────────────────────────────┘
         ↓
┌─────────────────────────────────┐
│ В стандарте есть что нужно?     │
├─────────────────────────────────┤
│ ДА → Настраивайте с ним         │
│ НЕТ → Продолжайте               │
└─────────────────────────────────┘
         ↓
┌─────────────────────────────────┐
│ Ищете конкретное поле?          │
├─────────────────────────────────┤
│ ДА → режим search_properties    │
│ НЕТ → Продолжайте               │
└─────────────────────────────────┘
         ↓
┌─────────────────────────────────┐
│ Все еще нужны детали?           │
├─────────────────────────────────┤
│ ДА → get_node({detail: "full"}) │
└─────────────────────────────────┘
```

## Глубокое Погружение в Зависимости Свойств

### Механизм displayOptions

**У полей есть правила видимости**:

```javascript
{
  "name": "body",
  "displayOptions": {
    "show": {
      "sendBody": [true],
      "method": ["POST", "PUT", "PATCH"]
    }
  }
}
```

**Перевод**: поле "body" показывается когда:
- sendBody = true И
- method = POST, PUT, или PATCH

### Общие Паттерны Зависимостей

#### Паттерн 1: Булевый Переключатель

**Пример**: HTTP Request sendBody
```javascript
// sendBody управляет видимостью body
{
  "sendBody": true   // → поле body появляется
}
```

#### Паттерн 2: Переключатель Операций

**Пример**: Slack ресурс/операция
```javascript
// Разные операции → разные поля
{
  "resource": "message",
  "operation": "post"
  // → Показывает: channel, text, attachments, и т.д.
}

{
  "resource": "message",
  "operation": "update"
  // → Показывает: messageId, text (другие поля!)
}
```

#### Паттерн 3: Выбор Типа

**Пример**: Условия узла IF
```javascript
{
  "type": "string",
  "operation": "contains"
  // → Показывает: value1, value2
}

{
  "type": "boolean",
  "operation": "equals"
  // → Показывает: value1, value2, другие операторы
}
```

### Поиск Зависимостей Свойств

**Используйте get_node с режимом search_properties**:
```javascript
get_node({
  nodeType: "nodes-base.httpRequest",
  mode: "search_properties",
  propertyQuery: "body"
});

// Возвращает пути свойств, соответствующие "body" с описаниями
```

**Или используйте полную детализацию для полной схемы**:
```javascript
get_node({
  nodeType: "nodes-base.httpRequest",
  detail: "full"
});

// Возвращает полную схему с правилами displayOptions
```

**Используйте это, когда**: Проверка не проходит, и вы не понимаете, почему поле отсутствует/обязательно

## Общие Паттерны Узлов

### Паттерн 1: Узлы Ресурс/Операция

**Примеры**: Slack, Google Sheets, Airtable

**Структура**:
```javascript
{
  "resource": "<сущность>",    // Какая вещь
  "operation": "<действие>",   // Что с ней делать
  // ... поля, специфичные для операции
}
```

**Как настроить**:
1. Выберите ресурс
2. Выберите операцию
3. Используйте get_node, чтобы увидеть требования для операции
4. Настройте обязательные поля

### Паттерн 2: Узлы на основе HTTP

**Примеры**: HTTP Request, Webhook

**Структура**:
```javascript
{
  "method": "<HTTP_METHOD>",
  "url": "<endpoint>",
  "authentication": "<тип>",
  // ... поля, специфичные для метода
}
```

**Зависимости**:
- POST/PUT/PATCH → sendBody доступно
- sendBody=true → body обязательно
- authentication != "none" → credentials обязательно

### Паттерн 3: Узлы Баз Данных

**Примеры**: Postgres, MySQL, MongoDB

**Структура**:
```javascript
{
  "operation": "<query|insert|update|delete>",
  // ... поля, специфичные для операции
}
```

**Зависимости**:
- operation="executeQuery" → query обязательно
- operation="insert" → table + values обязательно
- operation="update" → table + values + where обязательно

### Паттерн 4: Узлы Условной Логики

**Примеры**: IF, Switch, Merge

**Структура**:
```javascript
{
  "conditions": {
    "<тип>": [
      {
        "operation": "<оператор>",
        "value1": "...",
        "value2": "..."  // Только для бинарных операторов
      }
    ]
  }
}
```

**Зависимости**:
- Бинарные операторы (equals, contains, и т.д.) → value1 + value2
- Унарные операторы (isEmpty, isNotEmpty) → только value1 + singleValue: true

## Конфигурация, Специфичная для Операций

### Примеры Узла Slack

#### Отправка Сообщения (Post Message)
```javascript
{
  "resource": "message",
  "operation": "post",
  "channel": "#general",      // Обязательно
  "text": "Hello!",           // Обязательно
  "attachments": [],          // Опционально
  "blocks": []                // Опционально
}
```

#### Обновление Сообщения (Update Message)
```javascript
{
  "resource": "message",
  "operation": "update",
  "messageId": "1234567890",  // Обязательно (отличается от post!)
  "text": "Updated!",         // Обязательно
  "channel": "#general"       // Опционально (может быть выведено)
}
```

#### Создание Канала (Create Channel)
```javascript
{
  "resource": "channel",
  "operation": "create",
  "name": "new-channel",      // Обязательно
  "isPrivate": false          // Опционально
  // Примечание: text НЕ обязательно для этой операции
}
```

### Примеры Узла HTTP Request

#### GET Запрос
```javascript
{
  "method": "GET",
  "url": "https://api.example.com/users",
  "authentication": "predefinedCredentialType",
  "nodeCredentialType": "httpHeaderAuth",
  "sendQuery": true,                    // Опционально
  "queryParameters": {                  // Показывается, когда sendQuery=true
    "parameters": [
      {
        "name": "limit",
        "value": "100"
      }
    ]
  }
}
```

#### POST с JSON
```javascript
{
  "method": "POST",
  "url": "https://api.example.com/users",
  "authentication": "none",
  "sendBody": true,                     // Обязательно для POST
  "body": {                             // Обязательно при sendBody=true
    "contentType": "json",
    "content": {
      "name": "John Doe",
      "email": "john@example.com"
    }
  }
}
```

### Примеры Узла IF

#### Сравнение Строк (Бинарное)
```javascript
{
  "conditions": {
    "string": [
      {
        "value1": "={{$json.status}}",
        "operation": "equals",
        "value2": "active"              // Бинарное: нужно value2
      }
    ]
  }
}
```

#### Проверка на Пустоту (Унарное)
```javascript
{
  "conditions": {
    "string": [
      {
        "value1": "={{$json.email}}",
        "operation": "isEmpty",
        // Нет value2 - унарный оператор
        "singleValue": true             // Авто-добавляется при санитизации
      }
    ]
  }
}
```

## Обработка Условных Требований

### Пример: Тело HTTP Request

**Сценарий**: поле body обязательно, но только иногда

**Правило**:
```
body обязательно, когда:
  - sendBody = true И
  - method В (POST, PUT, PATCH, DELETE)
```

**Как обнаружить**:
```javascript
// Опция 1: Прочитать ошибку валидации
validate_node({...});
// Ошибка: "body required when sendBody=true"

// Опция 2: Поиск свойства
get_node({
  nodeType: "nodes-base.httpRequest",
  mode: "search_properties",
  propertyQuery: "body"
});
// Показывает: свойство body с правилами displayOptions

// Опция 3: Попробовать минимальную конфигурацию и итерировать
// Начните без body, валидация подскажет, если нужно
```

### Пример: singleValue Узла IF

**Сценарий**: свойство singleValue появляется для унарных операторов

**Правило**:
```
singleValue должно быть true, когда:
  - operation В (isEmpty, isNotEmpty, true, false)
```

**Хорошие новости**: Авто-санитизация исправляет это!

**Ручная проверка**:
```javascript
get_node({
  nodeType: "nodes-base.if",
  detail: "full"
});
// Показывает полную схему с правилами для операторов
```

## Анти-Паттерны Конфигурации

### ❌ Не делайте: Чрезмерная конфигурация заранее

**Плохо**:
```javascript
// Добавление каждого возможного поля
{
  "method": "GET",
  "url": "...",
  "sendQuery": false,
  "sendHeaders": false,
  "sendBody": false,
  "timeout": 10000,
  "ignoreResponseCode": false,
  // ... 20 других опциональных полей
}
```

**Хорошо**:
```javascript
// Начните с минимального
{
  "method": "GET",
  "url": "...",
  "authentication": "none"
}
// Добавляйте поля только при необходимости
```

### ❌ Не делайте: Пропуск Валидации

**Плохо**:
```javascript
// Настроить и развернуть без проверки
const config = {...};
n8n_update_partial_workflow({...});  // YOLO
```

**Хорошо**:
```javascript
// Проверить перед развертыванием
const config = {...};
const result = validate_node({...});
if (result.valid) {
  n8n_update_partial_workflow({...});
}
```

### ❌ Не делайте: Игнорирование Контекста Операции

**Плохо**:
```javascript
// Та же конфигурация для всех операций Slack
{
  "resource": "message",
  "operation": "post",
  "channel": "#general",
  "text": "..."
}

// Затем переключение операции без обновления конфигурации
{
  "resource": "message",
  "operation": "update",  // Изменено
  "channel": "#general",  // Неверное поле для update!
  "text": "..."
}
```

**Хорошо**:
```javascript
// Проверяйте требования при смене операции
get_node({
  nodeType: "nodes-base.slack"
});
// Смотрите, что нужно для операции update (messageId, а не channel)
```

## Лучшие Практики

### ✅ Делайте

1. **Начинайте с get_node (стандартная детализация)**
   - Ответ ~1-2K токенов
   - Покрывает 95% нужд конфигурации
   - Детализация по умолчанию

2. **Проверяйте итеративно**
   - Настроить → Проверить → Исправить → Повторить
   - В среднем 2-3 итерации — это нормально
   - Внимательно читайте ошибки валидации

3. **Используйте режим search_properties, когда застряли**
   - Если поле кажется отсутствующим, поищите его
   - Поймите, что управляет видимостью поля
   - `get_node({mode: "search_properties", propertyQuery: "..."})`

4. **Уважайте контекст операции**
   - Разные операции = разные требования
   - Всегда проверяйте get_node при смене операции
   - Не предполагайте, что конфиги переносимы

5. **Доверяйте авто-санитизации**
   - Структура оператора исправляется автоматически
   - Не добавляйте/удаляйте singleValue вручную
   - Метаданные IF/Switch добавляются при сохранении

### ❌ Не делайте

1. **Сразу переходить к detail="full"**
   - Попробуйте сначала стандартную детализацию
   - Повышайте только при необходимости
   - Полная схема — это 3-8K токенов

2. **Настраивать вслепую**
   - Всегда проверяйте перед развертыванием
   - Понимайте, почему поля обязательны
   - Используйте search_properties для условных полей

3. **Копировать конфиги без понимания**
   - Разные операции требуют разных полей
   - Проверяйте после копирования
   - Адаптируйте под новый контекст

4. **Вручную исправлять проблемы авто-санитизации**
   - Позвольте авто-санитизации обработать структуру оператора
   - Сосредоточьтесь на бизнес-логике
   - Сохраните и позвольте системе исправить структуру
