# Паттерны Промпт-инжиниринга (Prompt Engineering Patterns)

Освойте продвинутые техники промпт-инжиниринга для максимизации производительности, надежности и управляемости LLM.

## Когда использовать этот навык

- Проектирование сложных промптов для продакшен LLM-приложений
- Оптимизация производительности и согласованности промптов
- Внедрение паттернов структурированного рассуждения (chain-of-thought, tree-of-thought)
- Создание систем few-shot learning с динамическим выбором примеров
- Создание переиспользуемых шаблонов промптов с интерполяцией переменных
- Отладка и улучшение промптов, дающих нестабильные результаты
- Внедрение системных промптов для специализированных AI-ассистентов
- Использование структурированных выводов (JSON mode) для надежного парсинга

## Основные возможности

### 1. Few-Shot Learning (Обучение на примерах)

- Стратегии выбора примеров (семантическое сходство, выборка для разнообразия)
- Баланс количества примеров с ограничениями контекстного окна
- Создание эффективных демонстраций с парами вход-выход
- Динамическое извлечение примеров из баз знаний
- Обработка граничных случаев через стратегический выбор примеров

### 2. Chain-of-Thought Prompting (Цепочка рассуждений)

- Пошаговое извлечение рассуждений
- Zero-shot CoT с фразой "Давай подумаем шаг за шагом"
- Few-shot CoT со следами рассуждений
- Техники самосогласованности (выборка нескольких путей рассуждения)
- Шаги верификации и валидации

### 3. Structured Outputs (Структурированные выводы)

- Режим JSON для надежного парсинга
- Обеспечение схемы через Pydantic
- Типобезопасная обработка ответов
- Обработка ошибок для некорректных выводов

### 4. Оптимизация Промптов

- Рабочие процессы итеративного улучшения
- A/B тестирование вариаций промптов
- Измерение метрик производительности промптов (точность, согласованность, задержка)
- Снижение использования токенов при сохранении качества
- Обработка граничных случаев и режимов отказа

### 5. Системы Шаблонов

- Интерполяция переменных и форматирование
- Условные секции промптов
- Шаблоны для многоходовых диалогов
- Ролевая композиция промптов
- Модульные компоненты промптов

### 6. Дизайн Системных Промптов

- Настройка поведения модели и ограничений
- Определение форматов вывода и структуры
- Установление роли и экспертизы
- Правила безопасности и политики контента
- Установка контекста и справочной информации

## Быстрый Старт

```python
from langchain_anthropic import ChatAnthropic
from langchain_core.prompts import ChatPromptTemplate
from pydantic import BaseModel, Field

# Определение схемы структурированного вывода
class SQLQuery(BaseModel):
    query: str = Field(description="SQL запрос")
    explanation: str = Field(description="Краткое объяснение того, что делает запрос")
    tables_used: list[str] = Field(description="Список использованных таблиц")

# Инициализация модели со структурированным выводом
llm = ChatAnthropic(model="claude-sonnet-4-5")
structured_llm = llm.with_structured_output(SQLQuery)

# Создание шаблона промпта
prompt = ChatPromptTemplate.from_messages([
    ("system", """Вы эксперт по SQL. Генерируйте эффективные и безопасные SQL запросы.
    Всегда используйте параметризованные запросы для предотвращения SQL-инъекций.
    Кратко объясняйте свои рассуждения."""),
    ("user", "Преобразуй это в SQL: {query}")
])

# Создание цепочки
chain = prompt | structured_llm

# Использование
result = await chain.ainvoke({
    "query": "Найти всех пользователей, зарегистрировавшихся за последние 30 дней"
})
print(result.query)
print(result.explanation)
```

## Ключевые Паттерны

### Паттерн 1: Структурированный вывод с Pydantic

```python
from anthropic import Anthropic
from pydantic import BaseModel, Field
from typing import Literal
import json

class SentimentAnalysis(BaseModel):
    sentiment: Literal["positive", "negative", "neutral"]
    confidence: float = Field(ge=0, le=1)
    key_phrases: list[str]
    reasoning: str

async def analyze_sentiment(text: str) -> SentimentAnalysis:
    """Анализ тональности со структурированным выводом."""
    client = Anthropic()

    message = client.messages.create(
        model="claude-sonnet-4-5",
        max_tokens=500,
        messages=[{
            "role": "user",
            "content": f"""Проанализируй тональность этого текста.

Текст: {text}

Ответь в формате JSON, соответствующем этой схеме:
{{
    "sentiment": "positive" | "negative" | "neutral",
    "confidence": 0.0-1.0,
    "key_phrases": ["фраза1", "фраза2"],
    "reasoning": "краткое объяснение"
}}"""
        }]
    )

    return SentimentAnalysis(**json.loads(message.content[0].text))
```

### Паттерн 3: Few-Shot с Динамическим Выбором Примеров

```python
from langchain_voyageai import VoyageAIEmbeddings
from langchain_core.example_selectors import SemanticSimilarityExampleSelector
from langchain_chroma import Chroma

# Создание селектора примеров с семантическим сходством
example_selector = SemanticSimilarityExampleSelector.from_examples(
    examples=[
        {"input": "Как сбросить пароль?", "output": "Перейдите в Настройки > Безопасность > Сброс пароля"},
        {"input": "Где посмотреть историю заказов?", "output": "Перейдите в Аккаунт > Заказы"},
        {"input": "Как связаться с поддержкой?", "output": "Нажмите Помощь > Связаться с нами или напишите на support@example.com"},
    ],
    embeddings=VoyageAIEmbeddings(model="voyage-3-large"),
    vectorstore_cls=Chroma,
    k=2  # Выбрать 2 наиболее похожих примера
)

async def get_few_shot_prompt(query: str) -> str:
    """Создание промпта с динамически выбранными примерами."""
    examples = await example_selector.aselect_examples({"input": query})

    examples_text = "\n".join(
        f"Пользователь: {ex['input']}\nАссистент: {ex['output']}"
        for ex in examples
    )

    return f"""Вы полезный ассистент службы поддержки.

Вот несколько примеров взаимодействий:
{examples_text}

Теперь ответьте на этот запрос:
Пользователь: {query}
Ассистент:"""
```

### Паттерн 5: Восстановление после ошибок и Fallback

```python
from pydantic import BaseModel, ValidationError
import json

class ResponseWithConfidence(BaseModel):
    answer: str
    confidence: float
    sources: list[str]
    alternative_interpretations: list[str] = []

ERROR_RECOVERY_PROMPT = """
Ответь на вопрос на основе предоставленного контекста.

Контекст: {context}
Вопрос: {question}

Инструкции:
1. Если можешь ответить уверенно (>0.8), дай прямой ответ
2. Если уверен отчасти (0.5-0.8), дай лучший ответ с оговорками
3. Если не уверен (<0.5), объясни, какой информации не хватает
4. Всегда предлагай альтернативные интерпретации, если вопрос неоднозначен

Ответь в JSON:
{{
    "answer": "твой ответ или 'Я не могу определить это из контекста'",
    "confidence": 0.0-1.0,
    "sources": ["релевантные отрывки из контекста"],
    "alternative_interpretations": ["если вопрос неоднозначен"]
}}
"""

async def answer_with_fallback(
    context: str,
    question: str,
    llm
) -> ResponseWithConfidence:
    """Ответ с восстановлением после ошибок и фоллбэком."""
    prompt = ERROR_RECOVERY_PROMPT.format(context=context, question=question)

    try:
        response = await llm.ainvoke(prompt)
        return ResponseWithConfidence(**json.loads(response.content))
    except (json.JSONDecodeError, ValidationError) as e:
        # Fallback: попытка извлечь ответ без структуры
        simple_prompt = f"На основе: {context}\n\nОтвет: {question}"
        simple_response = await llm.ainvoke(simple_prompt)
        return ResponseWithConfidence(
            answer=simple_response.content,
            confidence=0.5,
            sources=["извлечение через fallback"],
            alternative_interpretations=[]
        )
```

## Лучшие Практики

1.  **Будьте Конкретны**: Расплывчатые промпты дают нестабильные результаты
2.  **Показывайте, а не Рассказывайте**: Примеры эффективнее описаний
3.  **Используйте Структурированные Выводы**: Применяйте схемы с Pydantic для надежности
4.  **Тестируйте Обширно**: Оценивайте на разнообразных, репрезентативных входных данных
5.  **Итерируйте Быстро**: Малые изменения могут иметь большое влияние
6.  **Мониторьте Производительность**: Отслеживайте метрики в продакшене
7.  **Контроль Версий**: Относитесь к промптам как к коду с правильным версионированием
8.  **Документируйте Намерения**: Объясняйте, почему промпты структурированы именно так

## Распространенные Ошибки

-   **Переусложнение**: Начинать со сложных промптов до того, как попробовать простые
-   **Загрязнение примерами**: Использование примеров, которые не соответствуют целевой задаче
-   **Переполнение контекста**: Превышение лимитов токенов избыточными примерами
-   **Неоднозначные инструкции**: Оставление места для множественных интерпретаций
-   **Игнорирование граничных случаев**: Не тестирование на необычных или граничных входных данных
-   **Нет обработки ошибок**: Предположение, что выводы всегда будут корректны
-   **Захардкоженные значения**: Отсутствие параметризации промптов для переиспользования

## Метрики Успеха

Отслеживайте эти KPI для ваших промптов:

-   **Точность**: Корректность выводов
-   **Согласованность**: Воспроизводимость на похожих входных данных
-   **Задержка (Latency)**: Время ответа (P50, P95, P99)
-   **Использование Токенов**: Среднее количество токенов на запрос
-   **Успешность (Success Rate)**: Процент валидных, парсируемых выводов
-   **Удовлетворенность Пользователей**: Оценки и отзывы
