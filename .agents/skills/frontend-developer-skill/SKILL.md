# Навык фронтенд-разработчика

## Цель

Предоставление полной экспертизы в области фронтенд-разработки для создания готовых к продакшену веб-приложений с использованием современных фреймворков (React, Vue, Next.js), настройки инструментов сборки, паттернов управления состоянием, инфраструктуры тестирования и стратегий оптимизации производительности.

## Когда использовать

- Создание новых приложений на React, Vue или Angular с нуля
- Настройка современных инструментов (Vite, ESLint, Prettier, фреймворки для тестирования)
- Внедрение управления состоянием с помощью Redux Toolkit, Zustand или Context API
- Настройка потоков аутентификации с управлением токенами и защищенными маршрутами
- Оптимизация размера бандла и производительности для продакшен-деплоя
- Создание библиотек компонентов и дизайн-систем
- Настройка комплексного тестирования (unit, интеграционное, E2E)

## Быстрый старт

**Вызывайте этот навык, когда нужно:**
- Создать приложение на React, Vue или Angular
- Настроить инструменты фронтенда (Vite, ESLint, Prettier)
- Внедрить управление состоянием (Redux Toolkit, Zustand, Context)
- Настроить процесс аутентификации
- Оптимизировать размер сборки и производительность
- Настроить тестирование (Vitest, Jest, Playwright)

**НЕ вызывайте, когда:**
- Нужен только бэкенд API → Используйте backend-developer
- Нужна оптимизация базы данных → Используйте database-optimizer
- Только DevOps/деплой → Используйте devops-engineer
- Нужен дизайн UI/UX без написания кода → Используйте ui-designer

## Структура принятия решений

### Выбор фреймворка

```
Выбор фронтенд-фреймворка
├─ Новый проект (с нуля)
│   ├─ Нужен SEO + серверный рендеринг (SSR)
│   │   ├─ Команда знает React → Next.js 14+
│   │   ├─ Команда знает Vue → Nuxt.js 3+
│   │   └─ Команда гибкая → Next.js (преимущество экосистемы)
│   │
│   ├─ SPA без требований к SSR
│   │   ├─ Опыт в React → React 18+ (Vite)
│   │   ├─ Опыт в Vue → Vue 3 (Vite)
│   │   └─ Enterprise/сложные формы → Angular 15+
│   │
│   └─ Статический сайт (блог, документация)
│       └─ Astro, Next.js SSG или Vite + React
│
└─ Существующий проект
    └─ Продолжайте работу на текущем фреймворке (для последовательности)
```

### Выбор управления состоянием

| Сценарий | Библиотека | Размер бандла | Кейс использования |
|----------|------------|---------------|--------------------|
| Простое локальное состояние | useState, useReducer | 0 КБ | Состояние на уровне компонента |
| Общее состояние (2-3 комп.) | Context API | 0 КБ | Тема, аутентификация, простой глобал |
| Среднее приложение (<10 слайсов) | Zustand | ~1 КБ | Большинство приложений, отличный DX |
| Крупное приложение (10+ слайсов) | Redux Toolkit | ~11 КБ | Enterprise, отладка Time-travel |
| Состояние сервера | TanStack Query | ~12 КБ | Данные API, кэширование |

### Подход к стилизации

```
Решение по стилизации
├─ Быстрое прототипирование → Tailwind CSS
├─ Библиотека компонентов → Radix UI + Tailwind
├─ Динамические темы → CSS-in-JS (Styled Components, Emotion)
├─ Большая команда → CSS Modules или Tailwind + Design Tokens
└─ Критично для производительности → Чистый CSS / SCSS
```

## Лучшие практики

1. **Используйте функциональные компоненты** — современный паттерн React
2. **Используйте хуки** — избегайте классовых компонентов, где это возможно
3. **Мемоизируйте тяжелые операции** — используйте useMemo, useCallback
4. **Ленивая загрузка компонентов** — для уменьшения начального размера бандла
5. **Типизируйте всё** — используйте возможности TypeScript
6. **Тщательно тестируйте** — Unit, интеграционные и E2E тесты
7. **Оптимизируйте изображения** — используйте современные форматы и lazy loading
8. **Внедряйте предохранители (Error Boundaries)** — для изящной обработки ошибок
9. **Соблюдайте доступность (Accessibility)** — ARIA-метки, навигация с клавиатуры
10. **Следите за производительностью** — отслеживайте показатели Core Web Vitals

## Общие паттерны

### Кастомные хуки

```typescript
function useFetch<T>(url: string) {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    fetch(url)
      .then(res => res.json())
      .then(setData)
      .catch(setError)
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}
```

### Контейнер / Презентационный компонент

```typescript
// Презентационный (глупый)
const UserList = ({ users, onUserClick }: UserListProps) => (
  <ul>
    {users.map(user => (
      <li key={user.id} onClick={() => onUserClick(user.id)}>
        {user.name}
      </li>
    ))}
  </ul>
);

// Контейнер (умный)
const UserListContainer = () => {
  const { users, fetchUsers } = useUsers();
  useEffect(() => fetchUsers(), [fetchUsers]);
  return <UserList users={users} onUserClick={handleClick} />;
};
```

## Устранение неполадок

### Общие проблемы

**Состояние не обновляется**
- Проверьте, используете ли вы правильный сеттер
- Проверьте массивы зависимостей в useEffect
- Убедитесь, что компоненты рендерятся повторно

**Компонент не рендерится повторно**
- Проверьте на наличие лишних предотвращений рендера
- Убедитесь, что мемоизация работает корректно
- Проверьте изменения пропсов

**Проблемы с производительностью**
- Профилируйте с помощью React DevTools
- Проверьте на наличие больших размеров бандла
- Изучите лишние ререндеры
- Внедрите разделение кода (code splitting)

**Тесты падают**
- Проверьте настройки тестов
- Изучите реализации моков
- Проверьте обработку асинхронности
- Убедитесь в правильной очистке после тестов

## Чек-лист качества

### Архитектура
- [ ] Обоснован выбор фреймворка
- [ ] Четкое управление состоянием (серверное и клиентское разделены)
- [ ] Логичная структура компонентов
- [ ] Внедрено разделение кода

### Качество кода
- [ ] Включен строгий режим TypeScript
- [ ] Настроены ESLint + Prettier
- [ ] Есть тесты для критических путей
- [ ] Отсутствует "прокидывание пропсов" (prop drilling), используется state management

### Производительность
- [ ] Оптимизирован размер бандла (<200 КБ в gzipped виде)
- [ ] Тяжелые операции мемоизированы
- [ ] Изображения оптимизированы (lazy loading, WebP)
- [ ] Оценена необходимость сторонних библиотек

### Тестирование
- [ ] Настроен фреймворк для тестирования
- [ ] Протестированы критические пути
- [ ] Имеются E2E тесты

### Безопасность
- [ ] Защищены переменные окружения
- [ ] Санитизация ввода (input sanitization)
- [ ] Токены авторизации защищены
- [ ] Проведен аудит зависимостей

## Паттерны интеграции

### react-specialist
- **Передача:** frontend-developer настраивает инструменты → react-specialist внедряет сложную логику компонентов
- **Инструменты:** Оба используют React; frontend-developer занимается экосистемой инструментов

### nextjs-developer
- **Передача:** Если требуется SSR/SEO → передача функций, специфичных для Next.js
- **Инструменты:** frontend-developer использует Vite/CRA; nextjs-developer использует Next.js App Router

### backend-developer
- **Передача:** frontend-developer внедряет API-клиент → backend-developer предоставляет контракты API
- **Инструменты:** frontend-developer использует Axios/Fetch, TanStack Query

### frontend-ui-ux-engineer
- **Передача:** frontend-developer настраивает структуру компонентов → frontend-ui-ux-engineer стилизует
- **Инструменты:** Оба используют React; frontend-ui-ux-engineer добавляет Framer Motion, дизайн-токены Tailwind
