# UI/UX Pro Max - Интеллект Дизайна

Комплексное руководство по дизайну для веб- и мобильных приложений. Содержит более 50 стилей, 97 цветовых палитр, 57 сочетаний шрифтов, 99 рекомендаций по UX и 25 типов диаграмм для 9 технологических стеков. База данных с поиском и рекомендациями на основе приоритетов.

## Когда применять

Обращайтесь к этим рекомендациям при:
- Проектировании новых UI-компонентов или страниц
- Выборе цветовых палитр и типографики
- Ревью кода на предмет проблем с UX
- Создании лендингов или дашбордов
- Внедрении требований к доступности

## Краткий справочник

### 1. Доступность (КРИТИЧЕСКОЕ)

- `color-contrast` — Минимальное соотношение 4.5:1 для обычного текста
- `focus-states` — Видимые кольца фокуса на интерактивных элементах
- `alt-text` — Описательный замещающий текст для значимых изображений
- `aria-labels` — aria-label для кнопок, состоящих только из иконок
- `keyboard-nav` — Порядок табуляции соответствует визуальному порядку
- `form-labels` — Используйте тег label с атрибутом for

### 2. Касание и взаимодействие (КРИТИЧЕСКОЕ)

- `touch-target-size` — Минимальный размер области касания 44x44px
- `hover-vs-tap` — Используйте клик/касание для основных взаимодействий
- `loading-buttons` — Отключайте кнопку во время асинхронных операций
- `error-feedback` — Четкие сообщения об ошибках рядом с проблемой
- `cursor-pointer` — Добавляйте cursor-pointer к кликабельным элементам

### 3. Производительность (ВЫСОКОЕ)

- `image-optimization` — Используйте WebP, srcset, ленивую загрузку
- `reduced-motion` — Проверяйте настройку prefers-reduced-motion
- `content-jumping` — Резервируйте место для асинхронного контента

### 4. Макет и адаптивность (ВЫСОКОЕ)

- `viewport-meta` — width=device-width initial-scale=1
- `readable-font-size` — Минимум 16px для основного текста на мобильных устройствах
- `horizontal-scroll` — Убедитесь, что контент вписывается в ширину вьюпорта
- `z-index-management` — Определите шкалу z-index (10, 20, 30, 50)

### 5. Типографика и цвет (СРЕДНЕЕ)

- `line-height` — Используйте 1.5–1.75 для основного текста
- `line-length` — Ограничивайте до 65–75 символов в строке
- `font-pairing` — Сочетайте "характеры" шрифтов заголовков и основного текста

### 6. Анимация (СРЕДНЕЕ)

- `duration-timing` — Используйте 150–300 мс для микровзаимодействий
- `transform-performance` — Используйте transform/opacity, а не width/height
- `loading-states` — Экраны-скелетоны (skeleton screens) или спиннеры

### 7. Выбор стиля (СРЕДНЕЕ)

- `style-match` — Соответствие стиля типу продукта
- `consistency` — Используйте один и тот же стиль на всех страницах
- `no-emoji-icons` — Используйте SVG-иконки, а не эмодзи

### 8. Графики и данные (НИЗКОЕ)

- `chart-type` — Соответствие типа графика типу данных
- `color-guidance` — Используйте доступные цветовые палитры
- `data-table` — Предоставляйте альтернативную таблицу для доступности

## Как использовать этот навык

Когда пользователь запрашивает работу над UI/UX (проектирование, сборка, создание, внедрение, ревью, исправление, улучшение), следуйте этому рабочему процессу:

### Шаг 1: Анализ требований пользователя

Извлеките ключевую информацию из запроса:
- **Тип продукта**: SaaS, e-commerce, портфолио, дашборд, лендинг и т. д.
- **Ключевые слова стиля**: минимализм, игривый, профессиональный, элегантный, темный режим и т. д.
- **Отрасль**: медицина, финтех, игры, образование и т. д.
- **Стек**: React, Vue, Next.js или по умолчанию `html-tailwind`

### Шаг 2: Генерация дизайн-системы (ОБЯЗАТЕЛЬНО)

**Всегда начинайте с `--design-system`**, чтобы получить комплексные рекомендации с обоснованием:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<product_type> <industry> <keywords>" --design-system [-p "Project Name"]
```

Эта команда:
1. Выполняет поиск по 5 областям параллельно (product, style, color, landing, typography)
2. Применяет правила обоснования из `ui-reasoning.csv` для выбора лучших совпадений
3. Возвращает полную дизайн-систему: паттерн, стиль, цвета, типографика, эффекты
4. Включает антипаттерны, которых следует избегать

**Пример:**
```bash
python3 skills/ui-ux-pro-max/scripts/search.py "beauty spa wellness service elegant" --design-system -p "Serenity Spa"
```

### Шаг 2b: Сохранение дизайн-системы (паттерн Master + Overrides)

Чтобы сохранить дизайн-систему для **иерархического извлечения в разных сессиях**, добавьте `--persist`:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<query>" --design-system --persist -p "Project Name"
```

Это создаст:
- `design-system/MASTER.md` — глобальный "источник истины" со всеми правилами дизайна
- `design-system/pages/` — папка для переопределений (overrides), специфичных для конкретных страниц

**С переопределением для конкретной страницы:**
```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<query>" --design-system --persist -p "Project Name" --page "dashboard"
```

Это также создаст:
- `design-system/pages/dashboard.md` — отклонения от мастер-файла для конкретной страницы

**Как работает иерархическое извлечение:**
1. При сборке конкретной страницы (например, "Оформление заказа"), сначала проверьте `design-system/pages/checkout.md`
2. Если файл страницы существует, его правила **переопределяют** мастер-файл
3. Если нет, используйте исключительно `design-system/MASTER.md`

**Подсказка для контекстного извлечения:**
```
Я создаю страницу [Название страницы]. Пожалуйста, прочитай design-system/MASTER.md.
Также проверь, существует ли design-system/pages/[page-name].md.
Если файл страницы существует, отдай приоритет его правилам.
Если нет, используй только правила из Master.
Теперь сгенерируй код...
```

### Шаг 3: Дополнение детальным поиском (при необходимости)

После получения дизайн-системы используйте поиск по областям (domains) для получения дополнительных деталей:

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<keyword>" --domain <domain> [-n <max_results>]
```

**Когда использовать детальный поиск:**

| Потребность | Область (Domain) | Пример |
|------|--------|---------|
| Больше вариантов стиля | `style` | `--domain style "glassmorphism dark"` |
| Рекомендации по графикам | `chart` | `--domain chart "real-time dashboard"` |
| Лучшие практики UX | `ux` | `--domain ux "animation accessibility"` |
| Альтернативные шрифты | `typography` | `--domain typography "elegant luxury serif"` |
| Структура лендинга | `landing` | `--domain landing "hero social-proof"` |

### Шаг 4: Руководства по стеку (По умолчанию: html-tailwind)

Получите лучшие практики реализации для конкретного стека. Если пользователь не указал стек, **используйте `html-tailwind`**.

```bash
python3 skills/ui-ux-pro-max/scripts/search.py "<keyword>" --stack html-tailwind
```

Доступные стеки: `html-tailwind`, `react`, `nextjs`, `vue`, `svelte`, `swiftui`, `react-native`, `flutter`, `shadcn`, `jetpack-compose`

## Общие правила для профессионального UI

Это часто упускаемые из виду проблемы, которые делают UI непрофессиональным:

### Иконки и визуальные элементы

| Правило | Как делать | Как НЕ делать |
|------|----|----- |
| **Никаких эмодзи-иконок** | Используйте SVG-иконки (Heroicons, Lucide, Simple Icons) | Используйте эмодзи 🎨 🚀 ⚙️ как иконки интерфейса |
| **Стабильные hover-состояния** | Используйте переходы цвета/прозрачности при наведении | Используйте трансформации масштаба, смещающие макет |
| **Правильные логотипы брендов** | Найдите официальный SVG в Simple Icons | Угадывайте или используйте неверные пути к логотипам |
| **Единый размер иконок** | Используйте фиксированный viewBox (24x24) с `w-6 h-6` | Смешивайте разные размеры иконок случайным образом |

### Взаимодействие и курсор

| Правило | Как делать | Как НЕ делать |
|------|----|----- |
| **Указатель курсора** | Добавляйте `cursor-pointer` ко всем кликабельным карточкам | Оставляйте дефолтный курсор на интерактивных элементах |
| **Обратная связь при наведении** | Обеспечьте визуальный отклик (цвет, тень, рамка) | Отсутствие индикации того, что элемент интерактивен |
| **Плавные переходы** | Используйте `transition-colors duration-200` | Мгновенная смена состояний или слишком медленно (>500 мс) |

### Контраст светлой/темной темы

| Правило | Как делать | Как НЕ делать |
|------|----|----- |
| **Стеклянные карточки (светлая тема)** | Используйте `bg-white/80` или выше | Используйте `bg-white/10` (слишком прозрачно) |
| **Контраст текста (светлая тема)** | Используйте `#0F172A` (slate-900) для основного текста | Используйте `#94A3B8` (slate-400) для основного текста |
| **Приглушенный текст (светлая тема)** | Используйте минимум `#475569` (slate-600) | Используйте gray-400 или светлее |
| **Видимость границ** | Используйте `border-gray-200` в светлой теме | Используйте `border-white/10` (невидимо) |

### Макет и отступы

| Правило | Как делать | Как НЕ делать |
|------|----|----- |
| **Плавающая навигация** | Добавляйте отступы `top-4 left-4 right-4` | Прилепляйте навигацию к краям `top-0 left-0 right-0` |
| **Отступы контента** | Учитывайте высоту фиксированной навигации | Позволяйте контенту скрываться под фиксированными элементами |
| **Единая макс-ширина** | Используйте одинаковую `max-w-6xl` или `max-w-7xl` | Смешивайте разную ширину контейнеров |

## Чеклист перед сдачей

Перед сдачей кода UI проверьте следующие пункты:

### Визуальное качество
- [ ] Эмодзи не используются в качестве иконок (используйте SVG)
- [ ] Все иконки из одного набора (Heroicons/Lucide)
- [ ] Логотипы брендов верны (проверено в Simple Icons)
- [ ] Состояния hover не вызывают смещения макета
- [ ] Цвета темы используются напрямую (`bg-primary`), без лишних оберток

### Взаимодействие
- [ ] Все кликабельные элементы имеют `cursor-pointer`
- [ ] Состояния hover дают четкую визуальную обратную связь
- [ ] Переходы плавные (150–300 мс)
- [ ] Состояния фокуса видимы при навигации с клавиатуры

### Светлая/Темная тема
- [ ] Текст в светлой теме имеет достаточный контраст (минимум 4.5:1)
- [ ] Стеклянные/прозрачные элементы видны в светлой теме
- [ ] Границы видны в обоих режимах
- [ ] Оба режима протестированы перед сдачей

### Макет
- [ ] Плавающие элементы имеют правильные отступы от краев
- [ ] Контент не скрыт под фиксированной навигацией
- [ ] Адаптивность проверена на 375px, 768px, 1024px, 1440px
- [ ] Нет горизонтальной прокрутки на мобильных устройствах

### Доступность
- [ ] У всех изображений есть альт-текст
- [ ] У полей ввода есть лейблы
- [ ] Цвет не является единственным индикатором
- [ ] `prefers-reduced-motion` учитывается
