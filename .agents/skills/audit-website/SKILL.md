# Навык аудита веб-сайтов

Аудит веб-сайтов на SEO, технические ошибки, качество контента, производительность и безопасность с помощью squirrelscan cli.

squirrelscan предоставляет инструмент squirrel — доступен для macOS, Windows и Linux. Он проводит глубокий аудит сайта, имитируя браузер и поисковый робот, анализируя структуру и контент на соответствие более чем 230 правилам.

Навык предоставляет список проблем и советы по их исправлению.

## Ссылки

* Сайт squirrelscan: [https://squirrelscan.com](https://squirrelscan.com)
* Документация (включая справочник правил): [docs.squirrelscan.com](https://docs.squirrelscan.com)

https://docs.squirrelscan.com/rules/{rule_category}/{rule_id}

Пример:
https://docs.squirrelscan.com/rules/links/external-links

## Что делает этот навык

Этот навык позволяет ИИ-агентам проверять сайты по более чем 230 правилам в 21 категории, включая:

- **SEO**: Мета-теги, заголовки, описания, канонические URL, Open Graph
- **Технические проблемы**: Битые ссылки, цепочки редиректов, скорость страницы, адаптивность
- **Производительность**: Время загрузки, использование ресурсов, кэширование
- **Качество контента**: Структура заголовков, alt-тексты изображений, анализ текста
- **Безопасность**: Утечки секретов, использование HTTPS, заголовки безопасности, смешанный контент
- **Доступность (A11y)**: Alt-тексты, контрастность цветов, навигация с клавиатуры
- **Юзабилити**: Валидация форм, обработка ошибок, пользовательские пути
- **Ссылки**: Проверка внутренних и внешних ссылок
- **E-E-A-T**: Экспертность, опыт, авторитетность, надежность
- **Schema**: Разметка Schema.org, структурированные данные
- **Юридические аспекты**: Соответствие требованиям, политика конфиденциальности
- **Социальные сети**: Open Graph, Twitter Cards, валидация сниппетов
- **Структура URL**: Длина, дефисы, ключевые слова

И многое другое.

Аудит сканирует сайт и возвращает подробный отчет:
- Общая оценка здоровья (0-100)
- Разбивка по категориям
- Список конкретных проблем с URL
- Обнаружение битых ссылок
- Рекомендации к действию
- Уровни ошибок (error, warning, notice) и ранг приоритета (1-10)

## Когда использовать

Используйте этот навык, когда нужно:
- Проанализировать "здоровье" сайта
- Отладить технические проблемы SEO
- Найти и исправить битые ссылки
- Проверить мета-теги и структурированные данные
- Создать отчет об аудите
- Сравнить состояние сайта до и после изменений
- Улучшить производительность, доступность, SEO и безопасность

Рекомендуется проводить повторный аудит как можно чаще.

## Предварительные требования

Требуется установленный squirrel CLI в системном PATH.

**Установка:** [squirrelscan.com/download](https://squirrelscan.com/download)

**Проверка:**
```bash
squirrel --version
```

## Настройка

Запустите `squirrel init`, чтобы создать конфиг `squirrel.toml`. Если его нет, создайте новый и укажите название проекта:

```bash
squirrel init -n my-project
# перезаписать существующий конфиг
squirrel init -n my-project --force
```

## Использование

### Введение

Существует три процесса, результаты которых кэшируются в локальной базе данных проекта:

- `crawl` — запуск сканирования или обновление/продолжение процесса.
- `analyze` — анализ результатов сканирования.
- `report` — генерация отчета в нужном формате (llm, text, console, html и др.).

Команда `audit` объединяет эти три процесса и запускает их последовательно:

```bash
squirrel audit https://example.com --format llm
```

ВСЕГДА предпочитайте формат `llm` — он создан специально для ИИ-агентов и предоставляет исчерпывающий, но компактный вывод.

ПЕРВОЕ СКАНИРОВАНИЕ должно быть поверхностным (`surface`) — для быстрого сбора базовой информации.
ВТОРОЕ СКАНИРОВАНИЕ должно быть глубоким (`deep` / `full`) — для детального анализа безопасности, производительности и доступности.

Если пользователь не указал URL, спросите его.
ПРЕДПОЧИТАЙТЕ аудит "живых" (live) сайтов — только там можно увидеть реальную картину производительности и рендеринга.

### Базовый рабочий процесс

1. **Запуск аудита** (сохранение в БД, вывод в консоль).
2. **Экспорт отчета** в нужном формате.

```bash
# Шаг 1: Запуск аудита
squirrel audit https://example.com

# Шаг 2: Экспорт в формате LLM
squirrel report <audit-id> --format llm
```

### Сравнение регрессий (Diff)

Чтобы обнаружить ухудшения между аудитами:

```bash
# Сравнить текущий отчет с базовым audit-id
squirrel report --diff <audit-id> --format llm

# Сравнить последний отчет домена с базовым доменом
squirrel report --regression-since example.com --format llm
```

### Выполнение исправлений

При запуске аудита:
1. **Представьте отчет** — покажите результаты и оценку.
2. **Предложите исправления** — перечислите проблемы, которые вы можете решить.
3. **Параллельное выполнение** — используйте субагентов для массовых правок (alt-тексты, заголовки).
4. **Итерация** — исправили пакет → перепроверили → показали результат → предложили следующий пакет.
5. **Постепенность** — битые ссылки и структурные изменения должны проверяться человеком.

### Целевые показатели (Score)

| Начальный балл | Целевой балл | Ожидаемая работа |
|----------------|--------------|------------------|
| < 50 (F) | 75+ (C) | Серьезные исправления |
| 50-70 (D) | 85+ (B) | Средние правки |
| 70-85 (C) | 90+ (A) | Полировка |
| > 85 (B+) | 95+ | Тонкая настройка |

Сайт считается ИСПРАВЛЕННЫМ, когда оценка выше 95 при полном покрытии (`--coverage full`).

## Параметры команды Audit

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `--format <fmt>` | Формат: console, text, json, html, markdown, llm | console |
| `--coverage <mode>`| Режим покрытия: quick, surface, full | surface |
| `--max-pages <n>` | Максимум страниц (до 5000) | зависит от режима |
| `--refresh` | Игнорировать кэш, сканировать всё заново | false |

### Режимы покрытия (Coverage)

| Режим | Страниц | Поведение | Кейс |
|-------|---------|-----------|------|
| `quick` | 25 | Только sitemaps, быстрый чек | CI проверки |
| `surface`| 100 | По одному примеру на паттерн URL | Обычный аудит |
| `full` | 500 | Сканирование всего до лимита | Глубокий анализ |

Режим `surface` интеллектуален: он находит паттерны типа `/blog/{slug}` и проверяет только один пример для экономии времени.

## Форматы вывода

### Формат LLM

Используйте `report --format llm`. Он на 40% компактнее XML и оптимизирован для контекста ИИ:
- **Summary**: Оценка и ключевые метрики.
- **Issues by Category**: Сгруппированные проблемы.
- **Broken Links**: Список битых ссылок.
- **Recommendations**: Приоритетные задачи с советами по исправлению.

## Устранение неполадок

### Команда squirrel не найдена
- Установите squirrel с [squirrelscan.com/download](https://squirrelscan.com/download).
- Убедитесь, что бинарный файл в вашем PATH (например, `~/.local/bin`).

### Неверный URL
- Всегда указывайте протокол: `https://example.com`.

## Как это работает
1. **Crawl**: Поиск и загрузка страниц.
2. **Analyze**: Проверка правил на каждой странице.
3. **External Links**: Проверка доступности внешних ссылок.
4. **Report**: Генерация отчета.
