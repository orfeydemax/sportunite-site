## Деплой сайта SPORT UNITE

Сайт `sportunitevn.com` задеплоен на GitHub Pages.

Факты деплоя:

* Домен: `sportunitevn.com`
* Файл домена в репозитории: `CNAME`
* Репозиторий: `https://github.com/orfeydemax/sportunite-site.git`
* Рабочая ветка для сайта: `sportunitevn.com`
* Удаленная ветка: `origin/sportunitevn.com`
* `www.sportunitevn.com` указывает CNAME на `orfeydemax.github.io`
* Apex-домен `sportunitevn.com` указывает на IP GitHub Pages:
  * `185.199.108.153`
  * `185.199.109.153`
  * `185.199.110.153`
  * `185.199.111.153`
* Живой сайт отвечает заголовком `Server: GitHub.com`

Когда пользователь просит "задеплой сайт" или "выложи изменения":

1. Проверить текущую ветку командой `git branch --show-current`.
2. Если ветка не `sportunitevn.com`, уточнить у пользователя или аккуратно перейти на эту ветку без потери локальных изменений.
3. Проверить изменения через `git status --short` и `git diff`.
4. Закоммитить только согласованные изменения.
5. Запушить в `origin sportunitevn.com`.
6. После пуша проверить живой сайт `https://sportunitevn.com/`.

Не деплоить через Netlify, Vercel, Firebase, Supabase Hosting или другие платформы, если пользователь явно не попросит изменить схему деплоя.

## Цикл самосовершенствования (Self-annealing loop)

Ошибки — это возможности для обучения. Когда что-то ломается:

1. Исправьте это
2. Обновите инструмент
3. Протестируйте инструмент, убедитесь, что он работает
4. Обновите директиву, чтобы включить новый поток
5. Теперь система стала сильнее

## Организация файлов

**Результаты против промежуточных файлов:**

* **Результаты (Deliverables):** Google Таблицы, Google Презентации или другие облачные выходные данные, к которым пользователь может получить доступ.
* **Промежуточные файлы (Intermediates):** Временные файлы, необходимые во время обработки.

**Структура каталогов:**

* `.tmp/` — Все промежуточные файлы (досье, данные парсинга, временные экспорты). Никогда не коммитить, всегда генерировать заново.
* `execution/` — Скрипты Python (детерминированные инструменты).
* `directives/` — регламенты (SOP) в формате Markdown (набор инструкций).
* `.env` — Переменные окружения и API-ключи.
* `credentials.json`, `token.json` — Учетные данные Google OAuth (обязательные файлы, в `.gitignore`).
* `requirements.txt` — Зависимости Python.

**Ключевой принцип:**
Локальные файлы предназначены только для обработки. Результаты живут в облачных сервисах (Google Таблицы, Презентации и т. д.), где пользователь может получить к ним доступ. Все в `.tmp/` можно удалить и сгенерировать заново.
